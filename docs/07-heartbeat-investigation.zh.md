## 1. 已确认的事实

[CONFIRMED] 旧工具的 `--poll` 按指定间隔发送 `01 0b 89 01`，它是 Hooks 模式的**读取**。这与 Studio 的专用心跳不同。本体离线时 dongle 也可能回复 Hooks 查询；往返成功不代表设备保持清醒。

[CONFIRMED] 对当前安装的 Studio 库进行 LLDB 反汇编，发现 `+[MessageHelper deviceHeartbeatMessage]` 构造 64 字节明文帧，开头为 `06 01 23 00 01`，随后为 59 个零字节。后台 worker 在连接状态允许时约每秒发送一次。`+[TimeUtils now]` 将 `CACurrentMediaTime` 乘以 1000，worker 将经过时间与 1000 比较。

```text
mov  w8, #0x106
movk w8, #0x23, lsl #16
str  w8, [sp, #0x8]
mov  w8, #0x1
strb w8, [sp, #0xc]

plaintext: 06 01 23 00 01 + 59 zero bytes
```

中间产物 `kwdm_message_builders.txt` 将该构造函数错误提取成 `01 00 00 00`：它把寄存器后续赋值错误归到了先前的存储指令。应以原始反汇编为证据。这是心跳帧，不代表可以发送其他具有相同 access 字节的未知命令。

## 2. 真实设备观测

测试只打开厂商接口。未观察到 Ulanzi Studio 进程，未打开输入接口，也未发送配置写入。每个窗口只在开始前和结束后查询在线状态，避免在线查询污染空闲区间。

| 窗口 | 时长 | 流量 | 结束状态 |
|---|---|---|---|
| 空闲 | 60.005 秒 | 零请求 | `06 03 0a 11 01 00 00 00` |
| Hooks 轮询 | 60.005 秒 | 30 次请求、30 次回复；间隔 2 秒 | `06 03 0a 11 01 00 00 00` |
| 稍后的 Studio 心跳尝试 | 起始检查即终止 | 只有状态查询；未发送心跳 | `06 03 0a 11 00 00 00 00` |
| 离线恢复诊断 | 约 20 秒 | 10 次 Studio 心跳发送调用成功；穿插状态查询 | `06 03 0a 11 00 00 00 00` |

[CONFIRMED] 两个已完成窗口结束时均在线，没有通知或回调异常。稍后的检查返回明确离线状态；此前尝试读取六个控件时未收齐配置快照，修订后的检查器已改为先验证在线状态。

[CONFIRMED] 用户报告已物理唤醒后，状态查询仍返回离线。单独的恢复诊断成功提交 10 帧已确认的 Studio 心跳，因穿插状态查询，实际间隔约两秒；每次状态仍为离线，六个控件的快照仍未收齐。没有通知或回调异常。这不否定用户的物理观察：测量的是 dongle 的无线在线标记。此次诊断没有获得在线起点，也不是一秒间隔的持续心跳测试。

[INFERRED] 更长时间空闲可能导致休眠。尚未测量确切状态切换时刻与原因。这些结果不能证明 Hooks 轮询是否防止休眠、专用心跳是否防止休眠，以及它能否唤醒已离线设备。这些尝试没有完成在线起点的 Studio 心跳窗口和键位前后比较。恢复连接后，通过运行中的工作台开展的验证记录在下文。

## 3. 运行中工作台验证

[CONFIRMED] 无线连接恢复后，真实本地工作台成功读取全部六个控件。键 1 从 `0x01` 改为 F13（`0x68`），收到了写确认且设备回读匹配，然后恢复为 `0x01`。最终全部六个控件配置与原快照一致。这验证了配置写入、读取和恢复路径，不代表已验证物理按键事件。完整往返保留在[工作台日志](evidence/2026-09-21-workspace-roundtrip.log)。

[CONFIRMED] 随后通过 HTTP 观察运行中的本地服务 **90.019 秒**，以约一秒间隔取得 91 个样本。每次均报告 `online=true`、`connected=true`，Studio 心跳开启、间隔一秒，且没有错误。观察到 `lastSent` 在 86 对相邻样本之间推进；采样时该时间戳距当前最多 1.001 秒。采样与心跳调度不同步，因此相邻时间戳相同不代表漏发心跳。窗口前后通过 `POST /api/refresh` 读取全部六个控件，配置完全一致。服务继续运行。见 [90 秒观测日志](evidence/2026-09-21-workspace-heartbeat90.log)。

这是成功的短时运行验证，不是隔离变量的防休眠实验：服务同时每两秒查询在线状态，前后读取键位也可能影响清醒状态。HTTP 状态读取只是观察现有服务，窗口内没有另开 HID 客户端或写入配置。这个历史窗口未验证长期休眠因果关系或物理按键事件；后续按键对照见下一节。

## 4. 心跳改变按键上报路径（2026-09-21）

[CONFIRMED] 后续真实 AU05 对照发现：Olanzi 每秒发送 `06 01 23 00 01` 时，普通按键不再通过标准 HID 注入，Fn 的标准输入回调也没有报文。保持厂商连接与心跳、仅关闭 Fn 标准输入接口，故障仍存在；仅停止心跳、保留厂商连接与只读查询后，Enter 恢复。因此不能把这次故障归因于 Fn 输入接口占用，也不能把这种心跳当作对输入路径无影响的纯保活。

| 现场条件 | 观察结果 |
|---|---|
| 每秒 Studio 心跳；厂商连接保持 | 普通键没有标准 HID 注入；Fn 标准输入回调无报文 |
| 保持心跳与厂商连接；关闭 Fn 标准输入接口 | 普通键仍失效 |
| 停止心跳；保留厂商连接和只读查询 | Enter 恢复 |
| 心跳运行时观察厂商通道 | 按键改以 `8b 10` 事件上报 |

[CONFIRMED] 厂商事件结合 Studio 的 AU05 `isSwitchKeyIndex=true` 路径，给出以下字段含义。`frame[2]` 是逻辑动作号，捕获示例为字节 `70`，不能直接作为 HID 键码；必须按物理控件索引读取已确认设备键位，再决定发送什么主机事件。

| 字段 | 已确认含义 |
|---|---|
| `frame[0] & 0x1F` | `0x0B`，通知命令 |
| `frame[1]` | `0x10`，按键事件子类型 |
| `frame[2]` | 逻辑动作号，不是 HID 键码 |
| `frame[3]` | `0x01` 按下，`0x00` 松开 |
| `frame[4]` | AU05 物理控件 index，按 Studio 的 `isSwitchKeyIndex=true` 解释 |

[CONFIRMED] 随后的六控件现场采集（17:28:35–17:28:42，见[厂商按键路由记录](evidence/2026-09-21-vendor-key-routing.log)）按用户操作顺序确认 `frame[4]` 为 0、1、2、3、4、5，与设备配置索引一致：顶部、中部、底部按键、旋钮按下、顺时针右拧、逆时针左拧。前四个动作均有按下/松开双沿；旋转 index 4 和 5 只上报 `status=1`，没有对应松开，主机须主动补松开形成脉冲，不能一直等待设备释放。该采集确认了六个实体到索引和两种旋转方向的映射，不等于六个动作的主机注入全部验证成功。

原生修复采用 `VendorKeyBridge`：消费这些厂商事件，按已确认设备映射转换普通键及 Fn，以 CoreGraphics 私有事件源向 HID 层投递。所有键的应用侧转换都需要相应权限，不能再只对 Fn 做权限门控。未知或多媒体映射须明确报错，不可把动作号猜成键码注入。本轮 68 项自动化测试及签名 Release 构建通过；已确认的物理端到端范围为下述 Enter 与顶部 Fn，不扩展为全部六个控件的系统动作验证。

[CONFIRMED] 修复版现场测试中，用户确认 Enter 换行和顶部 Fn 唤起豆包“好用！！”。`build/key-bridge-verification.log` 记录 17:31:22 的 Enter 虚拟键码 36 按下/松开，以及 17:31:24.285 的 Fn 虚拟键码 63 按下（flags 545259520）和 17:31:25.616 的松开（flags 536870912）；松开时 Fn 位已清除。当前日志证明一对 Fn 按下/松开，不声称两次完整测试，也不声称所有六个控件的系统动作均已实测。摘录统一保留在[厂商按键路由记录](evidence/2026-09-21-vendor-key-routing.log)。

早期“没有 Studio 就直出标准 HID”的结论仅适用于当时未发送该心跳的状态。官方 Studio 进程是否存在不是唯一条件；Olanzi 自行发送同一心跳也会改变上报路径。长时间防休眠效果仍需独立测量，按键路径切换不能证明休眠已解决。

## 5. 不写配置的复测方法

```bash
python3 tools/check_keepalive.py --seconds 60 --interval 2
python3 tools/check_keepalive.py --mode studio --seconds 60 --skip-idle --check-keys
```

默认模式比较空闲与 Hooks 轮询。Studio 模式使用已确认心跳，默认间隔为一秒，并可能切换到上述厂商按键上报路径；运行期间不能依赖普通键继续直接注入。`--skip-idle` 只执行选定模式。`--check-keys` 在窗口前后读取全部六个控件并比较配置字节；读取可能影响初始清醒状态，因此会显式记录并排除在计时窗口之外。如果起始状态未确认为在线，检查器不启动窗口便退出。

要进行更长时间的因果对照，每种模式均应从物理唤醒状态开始，保持供电条件一致，不操作控件，并测量超过已观察到的休眠时限。不要长按电源键。在线状态表示无线连接状态，不证明每个指示灯或节能子系统都清醒。不要根据没有回复推断关机。
