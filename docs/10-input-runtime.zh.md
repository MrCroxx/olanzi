## 1. 职责与范围

六个控件统一进入本机输入处理流程。菜单栏应用的设备工作线程持有接收器、心跳、手势时钟、已提交动作配置和合成按键状态。窗口只编辑草稿、提交配置，关闭窗口不会停止工作线程。它是进程内后台服务，不是另行安装的启动 daemon 或登录项；退出应用会停止转发。

上一版每次收到事件都查设备键位表，把硬件回退与运行时动作混在了一起，也没有识别双击和长按的位置。运行时现在优先加载本机持久配置；文件缺失时由界面直接提供自己的默认草稿，工作线程不从设备旧键位初始化，也不自动写文件。设备快照保持独立，刷新与重连不会替换本机配置或草稿，日常编辑不再发送硬件键位表写命令。

| 层 | 职责 |
|---|---|
| `MacHIDTransport` | 解码厂商帧并投递物理控件边沿，查询等待期间同样投递 |
| `GestureRouter` | 根据边沿与单调时钟期限识别手势，选定互斥的配置动作 |
| `VendorKeyBridge` | 路由选定动作、执行键盘按住、保留共享修饰键并重试释放失败 |
| `HostActionRunner` | 推进 APP 激活与顺序宏步骤，不阻塞设备工作线程 |
| `MacKeyEmitter` | 把键盘 usage 转换为 macOS 事件，投递至 HID 层 |
| `PhysicalFnMonitor` | 独立跟踪真实 Fn 元数据，避开合成事件的汇总状态反馈 |
| `HostKeymapStore` | 校验并原子持久化本机权威配置 |
| SwiftUI / `AppModel` | 编辑草稿、选择手势、导入导出配置、提交保存 |

厂商事件独立于配置动作标识控件。AU05 物理索引来自 `frame[4]`；`frame[2]` 是逻辑动作号，绝不作为键盘 usage 注入。四个可按压控件报告按下与松开边沿，旋转控件 4、5 每格仅报告按下脉冲。见[路径采集记录](evidence/2026-09-21-vendor-key-routing.log)。

## 2. 动作与时序

每个控件都有主要 `press` 动作。四个可按压控件还可以配置 `doublePress` 和 `longPress`。每个动作选择键盘条目、APP 目标或顺序宏；可按压控件还可将 MO 分配给单击或长按，见下文。键盘选择器为所选动作分配一个键，紧凑录制栏则可分配包含多个普通键和修饰键的组合。手势判定与键盘输出方式相互独立：单击、双击、长按均可选择 `tap`（短按一次）或 `burst`（连按），各自保存 2–20 次连按次数，默认 2 次。单击和长按还提供 `hold`（保持按住）：只有单击时跟随实体按下/松开，长按从阈值到达保持至实体松开。单击配置可选手势时等待判定，保持按住模式在单击判定后发送一次脉冲。双击在松开时判定，只支持短按一次或连按；旋转同样仅提供这两种脉冲模式，且拒绝双击/长按手势映射。仅连按模式显示行内次数步进器。未标记继承时，可选动作缺失表示关闭该手势；不执行动作键帽为双击/长按设置这种显式关闭覆盖，为单击设置显式无动作。标记透明继承的手势则从较低活动层继承动作、输出模式与次数。切换 APP、宏和 MO 不使用键盘输出模式或连按次数；切换 APP 和宏每次手势判定只执行一次。

APP 动作指定通过 `.app` 选择器选取的本机应用。执行时按需启动、请求激活，并在确认目标已进入前台后继续。宏包含 1–32 个不可嵌套的步骤，每步为切换 APP、键盘组合或等待 0.05–10 秒。步骤按配置顺序执行；键盘步骤发送一次脉冲，不会一直按住到后续步骤。编辑器可新增、删除和调整步骤顺序。APP 动作与宏串行执行。对于 APP 与宏执行，同一控件最多有一个排队或正在运行的动作，全局排队与运行中动作合计最多八个，额外触发会被忽略。宏键盘步骤按住 40 ms，APP 激活须在五秒内完成并确认前台；等待与激活均不阻塞心跳处理。

打开下半部按键选择区的宏分类，新建命名宏并点击**填入 Codex 聚焦宏**，模板将切换 `com.openai.codex`、等待 0.8 秒和 `⌃⌥⌘I` 填入编辑器。保存库项后，点击其 M 键帽分配给手势，再显式将完整草稿保存到本机。等待时间可按目标应用调整；前台确认并不证明特定输入框已就绪。新的直达流程仍须设备与目标应用实测。

编辑器围绕居中的设备示意图放置独立手势卡片：右侧三个按键各一张，左侧旋钮按下一张。每张卡片有三列，上方为手势名称、下方为当前动作，点击动作直接选择对应控件和手势。左右旋箭头位于旋钮两侧，各仅提供主要动作。不再另列重复控件列表；详细时序与 Fn 说明收在问号帮助中，正常运行不显示已保存标签和心跳计数，异常仍可见。

| 配置或事件 | 行为 |
|---|---|
| 没有可选手势 | 键盘主要动作的保持按住立即跟随实体按下/松开，短按一次或连按立即启动脉冲组；其他动作类型立即启动一次。 |
| 普通主要动作且仅配置长按 | 阈值前松开按主要动作所选输出模式执行（保持按住转为一次脉冲）；达到阈值后按保持按住、短按一次或连按执行键盘长按动作、启动一次切换 APP 或宏，或保持长按 MO 层至松开。 |
| 单击 MO 配置长按 | 主要层立即激活，长按动作在阈值到达时执行；长按 MO 替换此控件的层激活，其他长按动作使原层保持至实体松开。 |
| 配置双击 | 第一次松开后等待双击窗口，到期按主要动作所选输出模式执行（保持按住转为一次脉冲）。 |
| 双击期限前第二次按下 | 进入第二击候选，第二次松开后执行双击动作，键盘输出采用短按一次或连按。 |
| 第二次按压达到长按阈值 | 已配置的长按优先，不再补发等待中的主要或双击动作。 |
| 第二次按下恰好到期或已过期 | 先结算第一次主要动作，再由新的按下开始一轮手势。 |
| 旋转一格 | 立即触发主要动作；键盘输出采用短按一次或连按，不等待设备释放。 |

连按每次计划按住动作 40 ms，从松开到下一次按下间隔 80 ms。每次已判定的单击、双击、长按或旋转按对应手势的次数启动一组；触发后实体松开不取消剩余次数，继续按住不会重启整组。每个控件允许一个执行中的键盘动作及最多 16 个按 FIFO 顺序等待的动作；队列满时丢弃最新触发，不截断当前按下/松开对。长按连按沿用已有隔离规则，重复物理按下边沿不会成为新的长按手势。调度不阻塞工作线程；线程延迟时每次只推进一个边沿，并从实际推进时间安排下个期限，不追赶补发过期脉冲。输入暂停、断连、睡眠、权限丢失、配置替换或执行异常会取消待执行组及剩余次数，并尝试释放当前按键。单击、双击和旋转连按的实体行为仍待验证。

默认双击窗口从第一次松开起计 250 ms，长按阈值从对应按下起计 500 ms。配置允许双击窗口 150–500 ms、长按阈值 300–2000 ms，长按阈值必须大于双击窗口。计时使用单调时钟，重复按下报文不会重置按住状态或期限。

启用可选手势会推迟尚不能判定的普通主要动作；单击 MO 即使配置了长按也会立即生效。如果某个控件需要立即作为 Fn、Shift 等按住修饰键使用，应选择单击保持按住并关闭可选手势。长按动作分配为 Fn 并选择保持按住时，会在达到阈值后才开始按住 Fn，控件松开时释放；短按一次在阈值处发送一次 Fn 脉冲，连按则发送指定次数的脉冲；继续按住不会重复整组。单击 Fn 与其他手势并存、或双击映射为 Fn 时，手势判定后按所选模式发送一次或多次脉冲；此时单击保持按住转为一次脉冲。界面会说明持续按住与脉冲的区别，输入法实际效果仍须实测。

### 2.1 按住临时启用 Layer

四个固定层使用编号 0–3，没有自定义名称。Layer 0 始终提供完整的六控件基础映射，不允许继承。Layer 1–3 直接可用且默认透明继承。缺失控件记录时全部手势继承；已有记录可分别将单击、双击、长按标记为透明。各手势从编号最高的活动层依次向下解析，最终回落到 Layer 0，并随动作继承该手势的键盘输出模式与次数。显式单击无动作表示不执行，双击/长按无动作则关闭该手势，不再识别底层对应手势；两者都不是透明继承。已有无继承标记的控件记录仍完整覆盖该控件，包括已关闭的可选手势。

**Layer** 分类可将 **MO(n)** 分配给三个按键或旋钮按下的单击或长按。单击 MO 立即激活目标层，无需等待阈值。分配单击 MO 只清除双击，保留长按动作；双击、旋转、宏和动作库项不支持 MO。MO 目标限于 Layer 1–3；即使未编辑的目标层没有存储记录，也可正常分配。多个控件同时按住同一层时，只有最后一个控件松开才停用该层；多个层同时激活时按编号优先，而非按激活顺序优先。

单击 MO 可与键盘、APP 或宏长按动作并存。达到设定阈值后，长按按已有保持按住、短按一次或连按行为执行键盘动作，或启动一次切换 APP 或宏；单击 MO 激活保持到实体松开。松开控件立即撤销该次层激活，即使已经启动的键盘连按仍需完成剩余脉冲。如果长按也分配为 MO，达到阈值只替换此控件原先的单击层激活，改为长按目标层，其他控件的层激活不受影响。

普通单击也可搭配长按 MO：阈值前松开按原有单击/双击规则判定；达到阈值后激活长按目标层并保持到松开，不再补发等待中的单击或双击动作。这种配置可保留双击映射，沿用原有时序。长按 MO 始终等待设定的长按阈值，即使期间按了其他控件，也不会强制提前判为按住。键盘的保持按住、短按一次和连按选项不适用于 MO。

每次实体按下都会解析并保留该控件的映射，直至完整按住或手势序列结束，包括等待单击或双击判定的阶段。在另一控件按住期间切层，不会替换其动作或改变松开的对象。每次新的旋钮转动独立按当前活动层解析。取消输入时随手势和按键清理一并清除所有层激活；被取消的已按住 MO 控件必须先松开，才能再次激活层。

**0 1 2 3** 按钮始终在设备图上方横向展开，直接点击数字即可编辑对应层。继承的单击、双击、长按及旋钮左右转动均显示 VIA 式下三角箭头（`arrowtriangle.down`），悬停与无障碍文字明确说明继承底层。按键面板固定提供 **▽** 和**带叉圆角正方形（`xmark.square`，不执行动作）**，替代独立的清除动作与恢复继承按钮。非基础层点击 ▽ 仅将当前手势设为透明，保留同一控件其他手势的覆盖；Layer 0 不可使用。带叉正方形键帽将单击设为无动作，或关闭当前双击/长按。编辑层只预览该层控件，不会在输入工作线程中激活该层。动作库引用和 MO 目标编号会跨所有层检查。Layer 编辑保留在草稿中，只有**保存到本机**成功后才生效。

例如，先点 **1** 覆盖键 2 与旋钮转动，再点 **0** 将键 1 单击设为 MO(1)。保存到本机后，按住键 1 再操作这些控件。松开键 1 后，新按下使用其余活动层；如果键 2 仍按住，它会在松开时结束原先的 Layer 1 动作。这是主机端按住临时切层，可选按阈值触发的长按切层，本次不包含开关式切层。AU05 的实体 Layer 组合操作及其长按行为仍待验证。

## 3. 配置与迁移

活动映射保存于 `~/Library/Application Support/Olanzi/host-keymap.json`，包含六个唯一控件索引、动作条目、时间参数和格式版本。存储先校验再原子替换，持久化失败时不激活新配置。文件缺失时，工作线程发布 `hostConfigurationMissing=true`，不创建映射或写文件；应用直接提供 `HostKeymap.defaultKeymap` 可编辑草稿，不依赖设备是否连接或旧键位表里的动作类型。损坏或不支持的本机文件仍报错，须修复后重启应用，不能由草稿覆盖。只有显式保存成功后才持久化并激活新的本机映射；此前默认草稿不会启用心跳，整个过程不写设备键位表。

设备键位表是独立回退：应用退出、接收器恢复标准 HID 直出后使用。编辑回退仍是[03 · 工具手册](03-tool-manual.zh.md)中的显式协议工具操作，应用本机映射或导入配置不会改写它。设置页的“键位配置”区域可显式将只读设备键位快照导入草稿，必须通过全部六个控件的校验；失败时指出具体控件并保留当前草稿。该可选导入不属于初始化，也不激活配置。默认草稿和已有本机映射均支持离线编辑和保存；演示模式仅用内存，绝不接触真实本机存储或设备。

导出的 `HostProfile` 版本 2 包含每个控件的 `press`、可选 `doublePress` 和 `longPress` 动作，`pressBehavior`/`pressTapCount`、`doublePressBehavior`/`doublePressTapCount` 与 `longPressBehavior`/`longPressTapCount` 键盘输出设置，以及 `doublePressWindow`、`longPressThreshold` 时间参数，同时保留 APP 目标与完整宏步骤。已有仅键盘动作配置继续兼容。外层配置保持版本 2，内层 `HostKeymap` 在新增单击或双击输出设置偏离默认值，或存在手势继承标记时输出版本 5。各控件的 `inheritedGestures` 为 `Set<ControlGesture>`，可包含 `press`、`doublePress`、`longPress`；标记的手势继承动作与键盘输出设置。单击无动作保存为键盘键码 0，双击/长按无动作则为不带继承标记的 `nil`。缺失控件记录继承全部手势，已有无标记记录保留原先完整覆盖。无非默认输出设置或继承标记时沿用原有版本选择：包含 Layer 覆盖或 MO 动作时输出版本 4。存储保持稀疏：未编辑的 Layer 1–3 可不出现在 `layers` 中，MO(1)–MO(3) 无需对应存储记录即可使用。读取器兼容映射版本 1–5，旧键盘映射及内联 APP/宏动作保留为 Layer 0，Layer 1–3 透明继承。没有版本 5 设置、层记录或 MO 动作时，存在动作库或库引用仍输出版本 3，其他扩展动作输出版本 2，仅键盘映射输出版本 1。缺少 `pressBehavior` 和 `pressTapCount` 时默认 `hold` 与 2，缺少 `doublePressBehavior` 和 `doublePressTapCount` 时默认 `tap` 与 2。缺少 `longPressBehavior` 的旧配置按 `hold` 解析，缺少 `longPressTapCount` 时默认 2 次；已有长按模式与次数保留，旋转主要动作的旧 `hold` 仍执行一次脉冲；已有保持按住和短按一次行为不变，所有模式下次数都校验为 2–20。旋转控件不支持长按触发方式。双击和长按继续保留；跨 Mac 采用导出完整 JSON、在目标 Mac 导入并显式保存到本机的流程。不提供通过设备自动跨 Mac 同步，配置搬移不会写设备键位表。导入兼容旧版原生应用的版本 1 六键码配置，将其转为主要动作并关闭可选手势。已保存配置集合使用 `nativeHostProfiles`，旧 `nativeProfiles` 集合作为迁移来源保留。集合逐项解码与迁移，单项损坏或不支持不会阻止其他有效配置载入；包含失败项的完整原始数据另存于 `nativeHostProfilesRecoveryBackups`，后续保存或删除配置不会覆盖该恢复副本。导入限制为 32 KiB，并拒绝非法版本、重复或缺失控件、不支持的键、非法时间参数及旋转手势映射。

版本 3 新增 `actionLibrary`，其中 `NamedHostAction` 库项包含稳定 UUID `id`、1–80 字符 `name`、编号 `slot`，以及 APP 或宏 `action`。APP 使用 A0–A15，宏使用 M0–M15，两类独立分配编号。控件动作通过 UUID 引用库项，运行时在已保存映射中解析引用。库项不能再引用其他库项，也不能存储独立键盘动作。校验拒绝失效引用、重复 ID、同类重复编号及非法名称或动作；尚未分配给控件的库项也会保存与导出。编辑库项保留其身份，保存到本机后更新全部引用；删除被引用项会被拒绝，须先解除所有绑定。库编辑、分配与删除共用同一草稿及原子保存边界。

下半按键选择区的组合键分类通过同一本机映射流程录制同时按住的一组键，支持 A+B、Control+A+B、纯修饰键组合及 Fn，全部松开后完成并显示预览。单组合录制不保存宏时序；宏编辑器的连续录制通过 `MacroRecordingSession` 收集先后完成的组合及可选间隔。左右修饰键统一为左侧形式，Caps Lock 仍通过普通按键分类选择。**分配组合键**替换所选手势草稿，只有显式保存到本机成功后才持久化并激活映射。切换控件、手势、分类或离开 App 会停止捕获。系统占用的快捷键可能无法送达录制器。录制步骤见 [09 §4](09-native-macos.zh.md#4-本机动作与心跳)。

录制开始时会激活控件所在窗口并将键盘焦点移交录制区域；未录制时显示“尚未录制”，开始后显示“录制中”，收到按键后实时更新组合预览。完成结果独立发布，快速按下并松开也能生成可分配的预览。对于遗漏的松开事件，仅在短暂无事件后查询已经捕获的按键和修饰键是否释放，不从轮询新增组合内容。

宏代码是可视化模式同一组 `[MacroStep]` 值的编辑表示。`QMKMacroCodec` 只解析受支持的 QMK 语句子集，不编译 C、不运行任意函数，也不解释固件状态。切换 APP 和 Mac Fn 使用明确的 Olanzi 扩展。解析与步骤校验全部通过后才替换编辑器序列，因此无效代码会保留输入文本和原动作。转换成功不激活映射：保存库项更新草稿，页面底部保存到本机仍是持久化边界。代码文本、注释与排版不是第二套宏存储格式。支持语法与 Codex 示例见 [09 §4](09-native-macos.zh.md#4-本机动作与心跳)。

界面语言偏好独立于本机映射和导出的配置。跟随系统在系统语言未受支持时使用 English，也可显式选择 English 或简体中文。切换会即时更新界面并保存偏好，不替换活动映射、不丢弃草稿动作，也不翻译用户自定义的配置名称和文件路径。设置及权限欢迎页入口见 [09 · 原生 macOS App](09-native-macos.zh.md#3-窗口与菜单栏生命周期)。

保存请求使用独立请求 ID，并在快照中返回匹配的成功或失败结果。界面只根据自己提交的请求结果结束保存状态，不把刷新或重连产生的忙碌状态变化当作保存完成；保存期间的后续草稿编辑继续保留。

## 4. 按住、取消与失败处理

已发送的按住动作持有自身配置快照。同一个 Mac 键在不同控件间按引用计数管理，包括 Print Screen 与 F13 这类别名；释放一个控件不会提前释放另一个控件的键。事件标志保留其他仍在按住的修饰键，每格旋转都由主机补齐释放。

[CONFIRMED] F1–F20 的按下和松开还需携带事件自身的 function 标志；它与物理 Fn 使用相同的位，但不代表额外按住了 Fn。参见 Apple 的 [function 标志说明](https://developer.apple.com/documentation/appkit/nsevent/modifierflags-swift.struct/function)。2026-09-22 排查 F13 热键时发现，旧发射器覆盖事件标志后漏掉了这一位，新增的两项回归测试在修复前失败。现在按 macOS 虚拟键补齐该位，包括 Print Screen 等 F13–F15 别名；不将它们注册为持续修饰键，后续普通键和 Fn 松开仍清除合成反馈。修复后 173 项测试通过，使用原有钥匙串身份签名构建。实机日志记录了旋钮按下和松开对应的 F13 事件，以及同一时间的 Raycast 脚本成功记录；用户确认“两次都成功聚焦输入框”。这一确认覆盖当前脚本和配置，不代表所有应用热键均已验证。原始记录见 [F13 验证日志](evidence/2026-09-22-f13-hotkey.log)。

`PhysicalFnMonitor` 现在通过 session 层 listen-only `flagsChanged` tap 跟踪真实 Fn 与左右 Control、Shift、Option、Command。仅接收来源 PID 0，并只更新事件虚拟键码对应的侧键，不继承其他标志位，也不从系统汇总状态取种子，缓存初始为空。`VendorKeyBridge` 在转发前准备监听，失败时停止转发并明确报错；旧 `NativeFnBackend.open` 也在发送事件前启动该监听器并使用其 Fn 状态。主发射器先清除系统汇总标志中这些修饰键的家族位与侧位，再合并监听缓存与本应用持有的按住动作，Caps Lock 等其他状态保留原处理方式。tap 被禁用时，先清空失去可信度的缓存，再尝试重新启用；转发不会无限等待真实按键输入，下一个侧键事件重建该侧状态。启动前或漏报窗口中已按住的真实修饰键须松开再按。端口失效、创建或重新启用失败会报错；析构时移除并释放 run-loop source 与 tap。监听只读取修饰键元数据，不读取键盘文本。2026-09-22 的 00:42:57/59 日志已观察到一组来源 PID 0 的真实 Fn 按下/松开，不代表所有键盘交错场景，见[修饰键反馈摘录](evidence/2026-09-22-modifier-feedback.log)。修复后的两轮实测及其边界见下文。

输入暂停、断连、在线状态或权限丢失、系统睡眠、配置替换及退出都会清除所有临时层激活、取消未判定手势、待执行键盘组、剩余连按脉冲或宏步骤，并尝试释放本服务持有的按键。取消不会把延迟单击补发到新聚焦的应用。配置切换时仍按住的实体控件会等待物理松开后再接受新手势，防止把已有按住状态误解释成新配置动作。释放失败会保留待重试状态，不会当作已成功。睡眠通知立即阻止输入回调，工作线程随后取消手势并关闭连接；唤醒后仅在用户此前没有手动断开时重连，不补发睡前待判定动作。

APP 激活出错或超时会停止宏的剩余步骤。宏选定 APP 后，后续按键步骤要求该应用仍在前台；焦点变化会取消序列，避免将这些按键发送到其他应用。取消会使待完成的激活工作失效，迟到的完成通知不能恢复已取消的宏。目标应用可能在取消后才完成启动，但剩余宏按键不会补发。

Studio 心跳默认停用，仅在已成功保存的有效本机配置、已连接且在线的设备、输入监控与辅助功能权限及未暂停的输入同时就绪时启用。默认草稿尚未保存、本机配置文件错误或权限缺失时，厂商通道仍允许只读查询，心跳不会继续接管设备输入。权限诊断独立于配置初始化与设备在线状态。非演示模式缺少输入监控或辅助功能权限时，仅将 App 主窗口内容替换为权限欢迎页及授权引导，不另开弹窗、窗口或 sheet，也不进入配置工作区或设置界面；两项权限就绪后自动进入工作区，撤权则回到欢迎页，不堆叠初始化错误与页底提示。查询等待期间同样检查暂停条件；正常在线查询完成前保留上次确认的在线状态，避免每两秒取消一次按住动作。

空闲停止保活偏好保存在本机，独立于 `HostKeymap`、键位草稿和导出配置。默认永不停止，支持 1、5、10、15、30、60 分钟，在设置页的 Vibe Key 区域修改后立即生效。工作线程仅统计 Vibe Key 的物理按键和旋钮活动；控件按住期间不超时，松开后重新计时。只读状态与电量查询、电脑其他输入以及窗口显隐均不刷新活动期限。

到达期限后锁存空闲暂停，停止心跳和主机转发，取消手势、Layer、键盘输出组与宏，并释放合成按键。设备可能恢复固件键位；暂停期间厂商报文既不解除锁存，也不触发主机动作，避免标准 HID 恢复后双发。设置页或菜单栏显式恢复保活、接收器真正重连、Mac 唤醒或已确认的设备离线转在线会解除暂停并重新计时，仍受配置和权限条件约束。查询失败期间保留最后确认的在线状态：单纯从未知恢复在线不算重连，不会恢复保活。这些运行时规则不能证明设备实际休眠或省电效果。

界面权限状态由 App 每秒在主 run loop 的 common 模式中独立读取 `InputPermission.currentStatus()`，不依赖窗口激活或设备任务完成，也不弹出授权请求。轮询结果独立保存，较旧设备快照不能回滚它；只有状态变化才通知服务立即复查并自动切换欢迎页。停止或销毁模型时取消定时器，演示模式不读取真实权限。输入监控先读取 CG 监听预检，仅当其为假时创建 session 层、listen-only、仅键盘事件的短暂能力探针，检查有效且启用后立即释放，不加入 run loop 或读取事件；预检为真时跳过探针。预检或探针成功表示当前键盘监听能力“已就绪”，不是系统设置单个开关的镜像。HID 与事件合成预检仅保留诊断；辅助功能每次无条件读取 `AXIsProcessTrusted()`，避免任何其他预检短路掉真实 AX 状态。日志通过 `ListenProbe` 区分实际探针结果与跳过。

设备查询等待期间继续投递物理事件，因此回读不会把整个 Fn 按住过程压缩成查询结束后的两条事件。手势期限由后台工作线程维护，输入行为不依赖窗口计时器。显式导入设备键位、导入配置和校验本机动作时，未知动作类型与不支持的 macOS usage 会被拒绝，不猜测注入；普通设备回读中的不支持类型不会阻塞默认草稿或已有本机映射。此实现没有 F21–F24 的可用虚拟键映射。
