> 本文保留旧 Python / 浏览器工作台原型及 daemon 的操作记录。当前产品入口已改为 **[09 · Swift 原生 macOS App](09-native-macos.zh.md)**；下文命令、网页、终端授权和设置文件均仅适用于旧原型，不是原生 App 的运行要求。

## 1. 产品定位

这个旧原型探索了轻量本地 Studio 替代客户端的交互。键位配置是第一个模块；设备连接、状态与后台服务为后续能力提供基础。界面采用 VIA 默认 Olivia Dark 的暖杏色 `#E8C4B8` 与深灰背景，使用顶部图标导航、上方设备预览和下方键码区。设备预览按用户提供的实物照片绘制：银色长方形机身、顶部格栅、大圆旋钮和三个白色方键。控件布局和协议专门面向 AU05。

| 模块 | 当前支持 | 边界 |
|---|---|---|
| 键位配置 | 三个按键、旋钮按下、旋钮 → 右拧 / ← 左拧 | 共六个动作；硬件电源键不在可配置范围内 |
| 键码选择 | 单个普通键盘键码，包括单独的修饰键 | 不开放组合键、宏、系统/多媒体写入 |
| 浏览器输入测试 | 显示焦点浏览器页面接收到的键盘事件 | 无法判断来自哪把键盘；系统快捷键可能不会送到页面 |
| 本地配置文件 | 命名配置、JSON 导入导出、出厂键位草稿 | 保存在当前浏览器；导入或载入不会写设备 |
| Mac Fn 本机转换 | 将 AU05 的 `0x01` 转为当前 Mac 会话的 Fn 事件 | 默认关闭，需要输入监控与辅助功能权限、设备连接和持续运行的服务 |
| 设备连接 | 厂商通道连接、独立本体在线查询、后台心跳 | 接收器可用与本体在线是两种状态 |
| 后续模块 | 共用设备服务基础 | 不暴露灯效、固件 OTA 等尚未验证的写入 |

## 2. 启动与连接

### 前台运行

在 macOS 上，使用 Python 3 从仓库根目录启动：

```bash
python3 olanzi.py
```

服务会在当前终端前台运行，并在浏览器打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。全部界面资源来自本仓库，无需账户、CDN 或第三方 Python 包。HTTP 服务只绑定回环地址，并校验请求主机与修改请求来源。浏览器访问本地服务，由服务通过系统 IOKit 访问厂商 HID 接口。

1. 退出 Ulanzi Studio 和其他正在占用厂商通道的工具。
2. 插入接收器并打开 Vibe Key。
3. 等待服务自动连接并加载六个控件的当前映射；未连接时约每两秒重试，也可手动点击“连接 Vibe Key”。
4. 若接收器已连接但本体离线，打开设备并等待下一次在线检查。

```bash
# 不自动打开浏览器
python3 olanzi.py --no-browser

# 使用其他本地端口
python3 olanzi.py --port 8766

# 使用独立模拟设备预览，不访问真实硬件
python3 olanzi.py --demo
```

演示模式会在界面明确标注。模拟读写和连接状态不能证明真实硬件行为。真实设备访问失败时，服务不会悄悄切换到演示模式。

[03 · 工具手册](03-tool-manual.zh.md) 中的终端按键监控会打开键盘输入接口，需要输入监控权限。工作台里的浏览器输入测试使用页面键盘事件，不是原始 HID 抓包工具。可选 Mac Fn 转换会单独打开 AU05 标准输入接口，另需当前终端的输入监控和辅助功能权限；关闭该功能时不打开键盘接口。

### 后台运行

```bash
# 手动启动后台，不自动打开浏览器
python3 olanzi.py daemon start

# 查看后台进程状态及日志位置
python3 olanzi.py daemon status

# 停止本项目管理的后台进程
python3 olanzi.py daemon stop
```

启动后手动打开 [本地工作台](http://127.0.0.1:8765)。后台进程在关闭终端或浏览器后继续运行；它不是登录项或开机服务，本项目不会安装 `launchd`，系统重启后需要再次手动启动。普通 `python3 olanzi.py` 始终保留前台运行、默认打开浏览器的行为。

若已有前台服务占用同一个端口，后台启动会明确报错，不会杀死或替换现有服务。请先在原终端按 Ctrl-C，再运行后台启动命令。`daemon status` 检查受管理的后台进程，并不表示设备本体已经在线；设备连接和 Fn 运行状态仍在网页中查看。

后台日志位于 `~/Library/Logs/Olanzi/daemon.log`，进程记录位于 `~/Library/Application Support/Olanzi/daemon.json`。本机功能设置仍独立保存于 `~/Library/Application Support/Olanzi/settings.json`；启动或停止后台不会把这些设置变成浏览器配置，也不会删除设备内键位。

### 自动连接与主动断开

前台与后台服务启动后均自动连接设备，未连接时约每两秒重试。接收器已连接但本体离线时，会继续独立检查本体在线状态。网页中显式点击断开会暂停当前服务运行期间的自动连接，直到再次点击连接；这项暂停不持久化，下次启动服务仍会自动连接。

## 3. 编辑与应用键位

1. 在设备示意图或动作列表里选择控件。
2. 在键码选择区选择或搜索一个按键，改动暂存为草稿。
3. 核对待应用改动，再点击“应用到设备”。
4. 等待写确认与回读验证完成，才视为键位保存成功。

应用后的映射会持久化在设备内。软件会在写入前读取当前值；如果目标控件自加载后被其他程序改过，会拒绝过期写入并要求刷新。每个修改控件都必须收到匹配的写确认，并通过回读比对。

多控件应用不具备事务原子性。后面的写入失败时，前面的写入可能已经持久化。软件会报告部分失败，并尝试回读实际状态；若回读也失败，需要重新连接、刷新后再尝试。报错不代表所有改动都未生效。

界面会在丢弃未保存草稿前提醒。恢复出厂键位也只载入草稿，必须明确应用才会修改设备。出厂顶部按键是 ErrorRollOver 键码。若已启用 Mac Fn 本机转换，该键码会触发 Fn；否则仍由系统忽略。恢复出厂映射不会关闭本机转换开关。

已有组合键或系统/多媒体配置可作为原始配置读取，但选择器只创建已支持的单键映射。替换此类配置时，会移除该控件原先的多条目或非键盘定义。

## 4. 配置文件与输入测试

配置文件保存在当前浏览器的本地存储里。不同浏览器、浏览器配置或本地服务端口拥有独立存储；清除浏览器数据会删除已保存配置。可导出 JSON 作为便携备份。保存配置会记录当前草稿，载入或导入只更新草稿，不会立即写设备。

输入测试仅在开启测试且页面获得焦点时显示浏览器键盘事件。其他键盘也可能生成相同事件，浏览器无法确认是否来自 Vibe Key。系统保留快捷键、多媒体事件和某些按键可能不会送达页面。因此，页面没有显示事件，并不能证明没有 HID 报文。

## 5. 心跳与休眠

设备连接后，后台设备线程约每秒发送一次 Studio 心跳，使用明文前缀 `06 01 23 00 01` 并补零。该命令由本机 Studio 二进制的静态分析确认。本体在线状态另行约每两秒查询一次。主机侧发送成功本身不能证明设备已收到心跳或保持唤醒。

关闭浏览器标签页后，前台或后台服务和心跳仍继续运行。界面断开连接、Ctrl-C 停止前台服务、`daemon stop` 停止后台服务，或电脑进入睡眠，都会停止持续发送。命令调度共用设备线程，较慢的设备交换可能影响间隔。

旧的 `01 0b 89 01` 命令是 Hooks 查询，不是已确认的 Studio 心跳。接收器对它的回复不能证明本体在线或防止休眠。官方心跳与观察到的空闲休眠之间的关系，需要覆盖相应空闲时长的硬件观察；证据和实测边界见 [07 · 心跳调查](07-heartbeat-investigation.zh.md)。

## 6. 可选 Mac Fn 转换

在键码选择区的修饰键类别中选择 Mac Fn，再应用到设备；随后在界面开启本机 Fn 转换。设备端仍存储 `0x01`，由本地服务把相应标准 HID 报文转换为 Fn 事件。默认关闭，仅在显式点击权限按钮时请求系统授权；权限或接口不可用时显示原因并重试，不阻断原有厂商通道改键与心跳。

转换要求设备已连接且本体在线、服务持续运行，以及运行终端获得输入监控与辅助功能权限。浏览器关闭后仍可运行，后台模式也会保留转换，但服务停止后不再转换。每个配置为该键码的控件都会触发 Fn，无法区分多个同码物理控件；不要把这个能力当作设备固件原生 Fn。

开关保存在 `~/Library/Application Support/Olanzi/settings.json`，与浏览器配置文件分离，JSON 配置导入导出不包含该开关。演示模式不会打开真实输入接口或注入系统 Fn。具体按下/松开行为、权限步骤和未实测的系统动作见 [08 · Mac Fn](08-mac-fn.zh.md)。

## 7. 架构与扩展边界

| 文件或目录 | 职责 |
|---|---|
| `olanzi.py` | 回环 HTTP 入口、本地资源、请求校验、浏览器启动 |
| `olanzi_device.py` | macOS HID 传输、演示传输、串行设备线程、状态、心跳与核验写入 |
| `olanzi_fn.py` | 独立 AU05 输入接口、权限状态、Fn 按下/松开及故障释放 |
| `olanzi_settings.py` | 本机 Fn 开关的独立持久化 |
| `olanzi_daemon.py` | 手动启动、检查和停止后台进程，保存独立进程记录与日志 |
| `web/` | 原生 HTML / CSS / JavaScript 界面、键位草稿、配置存储、浏览器输入测试 |
| `vibekey.py` | 原有终端工具与已恢复的协议基础能力 |
| `tests/` | 设备行为、HTTP 边界与前端校验测试 |

HTTP 请求线程把任务提交给唯一的设备线程，让厂商通道的读、写和心跳共用一条串行连接。可选 Fn 转换由同一线程管理独立的标准输入接口。前端区分可编辑草稿与最近一次设备快照。配置文件与设备持久化相互独立，载入配置不会隐式应用。

新增模块应复用设备服务，保留明确的读写边界，只暴露参数格式经过验证的命令。逆向命令表能证明命令存在，但不等于允许发送其中的所有写命令。固件 OTA、灯效与其他设备功能在实现前，都需要独立的协议验证。

## 8. 验证

在仓库根目录运行：

```bash
python3 -m unittest discover -s tests -v
node --test tests/test_frontend.mjs
python3 tools/check_docs.py
git diff --check
```

Python 运行时只依赖标准库。Node.js 用于前端测试，启动工作台不需要它。

模拟和演示测试验证应用逻辑、写确认、回读处理、过期写入拒绝、部分失败与本地 HTTP 边界。它们不能证明无线送达、断电后的设备持久化、每一个可选按键的行为，或空闲防休眠效果。Fn 状态机测试也不能证明系统地球键动作、听写或与硬件 Fn 完全等效。硬件观察应写入[验证记录](05-verification-log.zh.md)和[心跳调查](07-heartbeat-investigation.zh.md)，未实测结论必须明确保持未确认状态。
