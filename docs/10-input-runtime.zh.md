## 1. 职责与范围

六个控件统一进入本机输入处理流程。菜单栏应用的设备工作线程持有接收器、心跳、手势时钟、已提交动作配置和合成按键状态。窗口只编辑草稿、提交配置，关闭窗口不会停止工作线程。它是进程内后台服务，不是另行安装的启动 daemon 或登录项；退出应用会停止转发。

上一版每次收到事件都查设备键位表，把硬件回退与运行时动作混在了一起，也没有识别双击和长按的位置。运行时现在优先加载本机持久配置；文件缺失时由界面直接提供自己的默认草稿，工作线程不从设备旧键位初始化，也不自动写文件。设备快照保持独立，刷新与重连不会替换本机配置或草稿，日常编辑不再发送硬件键位表写命令。

| 层 | 职责 |
|---|---|
| `MacHIDTransport` | 解码厂商帧并投递物理控件边沿，查询等待期间同样投递 |
| `GestureRouter` | 根据边沿与单调时钟期限识别手势，选定互斥的配置动作 |
| `VendorKeyBridge` | 执行动作的按住状态、保留共享修饰键、重试失败的释放 |
| `MacKeyEmitter` | 把键盘 usage 转换为 macOS 事件，投递至 HID 层 |
| `PhysicalFnMonitor` | 独立跟踪真实 Fn 元数据，避开合成事件的汇总状态反馈 |
| `HostKeymapStore` | 校验并原子持久化本机权威配置 |
| SwiftUI / `AppModel` | 编辑草稿、选择手势、导入导出配置、提交保存 |

厂商事件独立于配置动作标识控件。AU05 物理索引来自 `frame[4]`；`frame[2]` 是逻辑动作号，绝不作为键盘 usage 注入。四个可按压控件报告按下与松开边沿，旋转控件 4、5 每格仅报告按下脉冲。见[路径采集记录](evidence/2026-09-21-vendor-key-routing.log)。

## 2. 动作与时序

每个控件都有主要 `press` 动作。四个可按压控件还可以配置 `doublePress` 和 `longPress`。动作包含键盘条目。键盘选择器为所选动作分配一个键，紧凑录制栏则可分配包含多个普通键和修饰键的组合。长按动作还包含 `longPressBehavior`：`hold`（默认）在阈值后保持至实体松开，`tap` 在阈值处发送一次按下/松开脉冲，继续按住不重复。仅编辑长按时显示紧凑的触发方式选择器，对应保持按住和短按一次。可选动作缺失表示关闭该手势，分配“未分配”键则表示有意不执行。旋转控件拒绝双击与长按配置。

编辑器围绕居中的设备示意图放置独立手势卡片：右侧三个按键各一张，左侧旋钮按下一张。每张卡片有三列，上方为手势名称、下方为当前动作，点击动作直接选择对应控件和手势。左右旋箭头位于旋钮两侧，各仅提供主要动作。不再另列重复控件列表；详细时序与 Fn 说明收在问号帮助中，正常运行不显示已保存标签和心跳计数，异常仍可见。

| 配置或事件 | 行为 |
|---|---|
| 没有可选手势 | 主要动作立即按下，随实体松开释放，Fn 和修饰键不增加手势延迟。 |
| 仅配置长按 | 阈值前松开发送一次主要动作脉冲；达到阈值后按保持按住或短按一次执行长按动作。 |
| 配置双击 | 第一次松开后等待双击窗口，到期发送一次主要动作脉冲。 |
| 双击期限前第二次按下 | 进入第二击候选，第二次松开后发送一次双击动作脉冲。 |
| 第二次按压达到长按阈值 | 已配置的长按优先，不再补发等待中的主要或双击动作。 |
| 第二次按下恰好到期或已过期 | 先结算第一次主要动作，再由新的按下开始一轮手势。 |
| 旋转一格 | 立即发送一次主要动作的按下与松开，不等待设备释放。 |

默认双击窗口从第一次松开起计 250 ms，长按阈值从对应按下起计 500 ms。配置允许双击窗口 150–500 ms、长按阈值 300–2000 ms，长按阈值必须大于双击窗口。计时使用单调时钟，重复按下报文不会重置按住状态或期限。

启用可选手势必然会推迟尚不能判定的主要动作。如果某个控件需要立即作为 Fn、Shift 等按住修饰键使用，应关闭其可选手势。长按动作分配为 Fn 并选择保持按住时，会在达到阈值后才开始按住 Fn，控件松开时释放；短按一次则在阈值处发送一次 Fn 脉冲，继续按住不重复。单击 Fn 与其他手势并存、或双击映射为 Fn 时，手势判定后执行脉冲。界面会说明持续按住与脉冲的区别，输入法实际效果仍须实测。

## 3. 配置与迁移

活动映射保存于 `~/Library/Application Support/Olanzi/host-keymap.json`，包含六个唯一控件索引、动作条目、时间参数和格式版本。存储先校验再原子替换，持久化失败时不激活新配置。文件缺失时，工作线程发布 `hostConfigurationMissing=true`，不创建映射或写文件；应用直接提供 `HostKeymap.defaultKeymap` 可编辑草稿，不依赖设备是否连接或旧键位表里的动作类型。损坏或不支持的本机文件仍报错，须修复后重启应用，不能由草稿覆盖。只有显式保存成功后才持久化并激活新的本机映射；此前默认草稿不会启用心跳，整个过程不写设备键位表。

设备键位表是独立回退：应用退出、接收器恢复标准 HID 直出后使用。编辑回退仍是[03 · 工具手册](03-tool-manual.zh.md)中的显式协议工具操作，应用本机映射或导入配置不会改写它。配置页可显式将只读设备键位快照导入草稿，必须通过全部六个控件的校验；失败时指出具体控件并保留当前草稿。该可选导入不属于初始化，也不激活配置。默认草稿和已有本机映射均支持离线编辑和保存；演示模式仅用内存，绝不接触真实本机存储或设备。

导出的 `HostProfile` 版本 2 包含每个控件的 `press`、可选 `doublePress` 和 `longPress` 动作，`longPressBehavior` 值（`hold` 或 `tap`），以及 `doublePressWindow`、`longPressThreshold` 时间参数。缺少 `longPressBehavior` 的旧配置按 `hold` 解析，旋转控件不支持长按触发方式。双击和长按继续保留；跨 Mac 采用导出完整 JSON、在目标 Mac 导入并显式保存到本机的流程。不提供通过设备自动跨 Mac 同步，配置搬移不会写设备键位表。导入兼容旧版原生应用的版本 1 六键码配置，将其转为主要动作并关闭可选手势。已保存配置集合使用 `nativeHostProfiles`，旧 `nativeProfiles` 集合作为迁移来源保留。集合逐项解码与迁移，单项损坏或不支持不会阻止其他有效配置载入；包含失败项的完整原始数据另存于 `nativeHostProfilesRecoveryBackups`，后续保存或删除配置不会覆盖该恢复副本。导入限制为 32 KiB，并拒绝非法版本、重复或缺失控件、不支持的键、非法时间参数及旋转手势映射。

动作标题旁的紧凑录制栏通过同一本机映射流程编辑当前动作草稿，原地显示完整组合，较长组合可水平滚动或悬停查看；下方键盘保持可见，录制期间禁用。它捕获当前 App 窗口中同时按住的一组按键，支持 A+B、Control+A+B、纯修饰键组合及 Fn；全部按键松开后完成该组并显示预览。录制结果表示同时按住的多个键，不保存宏的时序。左右修饰键统一为左侧形式，Caps Lock 仍通过现有键盘列表选择。**重新录制**替换待确认的录制结果，**使用组合键**替换所选动作草稿，只有显式保存到本机成功后才会持久化并激活映射。取消保留原草稿；切换控件、动作、页面或离开 App 都会结束捕获。系统占用的快捷键可能无法送达录制器。录制步骤见 [09 · 原生 macOS App](09-native-macos.zh.md#4-本机动作与心跳)。

界面语言偏好独立于本机映射和导出的配置。跟随系统在系统语言未受支持时使用 English，也可显式选择 English 或简体中文。切换会即时更新界面并保存偏好，不替换活动映射、不丢弃草稿动作，也不翻译用户自定义的配置名称和文件路径。设置及权限欢迎页入口见 [09 · 原生 macOS App](09-native-macos.zh.md#3-窗口与菜单栏生命周期)。

保存请求使用独立请求 ID，并在快照中返回匹配的成功或失败结果。界面只根据自己提交的请求结果结束保存状态，不把刷新或重连产生的忙碌状态变化当作保存完成；保存期间的后续草稿编辑继续保留。

## 4. 按住、取消与失败处理

已发送的按住动作持有自身配置快照。同一个 Mac 键在不同控件间按引用计数管理，包括 Print Screen 与 F13 这类别名；释放一个控件不会提前释放另一个控件的键。事件标志保留其他仍在按住的修饰键，每格旋转都由主机补齐释放。

[CONFIRMED] F1–F20 的按下和松开还需携带事件自身的 function 标志；它与物理 Fn 使用相同的位，但不代表额外按住了 Fn。参见 Apple 的 [function 标志说明](https://developer.apple.com/documentation/appkit/nsevent/modifierflags-swift.struct/function)。2026-09-22 排查 F13 热键时发现，旧发射器覆盖事件标志后漏掉了这一位，新增的两项回归测试在修复前失败。现在按 macOS 虚拟键补齐该位，包括 Print Screen 等 F13–F15 别名；不将它们注册为持续修饰键，后续普通键和 Fn 松开仍清除合成反馈。修复后 173 项测试通过，使用原有钥匙串身份签名构建。实机日志记录了旋钮按下和松开对应的 F13 事件，以及同一时间的 Raycast 脚本成功记录；用户确认“两次都成功聚焦输入框”。这一确认覆盖当前脚本和配置，不代表所有应用热键均已验证。原始记录见 [F13 验证日志](evidence/2026-09-22-f13-hotkey.log)。

`PhysicalFnMonitor` 现在通过 session 层 listen-only `flagsChanged` tap 跟踪真实 Fn 与左右 Control、Shift、Option、Command。仅接收来源 PID 0，并只更新事件虚拟键码对应的侧键，不继承其他标志位，也不从系统汇总状态取种子，缓存初始为空。`VendorKeyBridge` 在转发前准备监听，失败时停止转发并明确报错；旧 `NativeFnBackend.open` 也在发送事件前启动该监听器并使用其 Fn 状态。主发射器先清除系统汇总标志中这些修饰键的家族位与侧位，再合并监听缓存与本应用持有的按住动作，Caps Lock 等其他状态保留原处理方式。tap 被禁用时，先清空失去可信度的缓存，再尝试重新启用；转发不会无限等待真实按键输入，下一个侧键事件重建该侧状态。启动前或漏报窗口中已按住的真实修饰键须松开再按。端口失效、创建或重新启用失败会报错；析构时移除并释放 run-loop source 与 tap。监听只读取修饰键元数据，不读取键盘文本。2026-09-22 的 00:42:57/59 日志已观察到一组来源 PID 0 的真实 Fn 按下/松开，不代表所有键盘交错场景，见[修饰键反馈摘录](evidence/2026-09-22-modifier-feedback.log)。修复后的两轮实测及其边界见下文。

断连、在线状态或权限丢失、系统睡眠、配置替换及退出都会取消未判定手势，并尝试释放本服务持有的按键。取消不会把延迟单击补发到新聚焦的应用。配置切换时仍按住的实体控件会等待物理松开后再接受新手势，防止把已有按住状态误解释成新配置动作。释放失败会保留待重试状态，不会当作已成功。睡眠通知立即阻止输入回调，工作线程随后取消手势并关闭连接；唤醒后仅在用户此前没有手动断开时重连，不补发睡前待判定动作。

Studio 心跳默认停用，仅在已成功保存的有效本机配置、已连接且在线的设备、输入监控与辅助功能权限及未暂停的输入同时就绪时启用。默认草稿尚未保存、本机配置文件错误或权限缺失时，厂商通道仍允许只读查询，心跳不会继续接管设备输入。权限诊断独立于配置初始化与设备在线状态。非演示模式缺少输入监控或辅助功能权限时，仅将 App 主窗口内容替换为权限欢迎页及授权引导，不另开弹窗、窗口或 sheet，也不进入配置工作区或设置界面；两项权限就绪后自动进入工作区，撤权则回到欢迎页，不堆叠初始化错误与页底提示。查询等待期间同样检查暂停条件；正常在线查询完成前保留上次确认的在线状态，避免每两秒取消一次按住动作。

界面权限状态由 App 每秒在主 run loop 的 common 模式中独立读取 `InputPermission.currentStatus()`，不依赖窗口激活或设备任务完成，也不弹出授权请求。轮询结果独立保存，较旧设备快照不能回滚它；只有状态变化才通知服务立即复查并自动切换欢迎页。停止或销毁模型时取消定时器，演示模式不读取真实权限。输入监控先读取 CG 监听预检，仅当其为假时创建 session 层、listen-only、仅键盘事件的短暂能力探针，检查有效且启用后立即释放，不加入 run loop 或读取事件；预检为真时跳过探针。预检或探针成功表示当前键盘监听能力“已就绪”，不是系统设置单个开关的镜像。HID 与事件合成预检仅保留诊断；辅助功能每次无条件读取 `AXIsProcessTrusted()`，避免任何其他预检短路掉真实 AX 状态。日志通过 `ListenProbe` 区分实际探针结果与跳过。

设备查询等待期间继续投递物理事件，因此回读不会把整个 Fn 按住过程压缩成查询结束后的两条事件。手势期限由后台工作线程维护，输入行为不依赖窗口计时器。显式导入设备键位、导入配置和校验本机动作时，未知动作类型与不支持的 macOS usage 会被拒绝，不猜测注入；普通设备回读中的不支持类型不会阻塞默认草稿或已有本机映射。此实现没有 F21–F24 的可用虚拟键映射。

## 5. 验证与扩展边界

自动测试覆盖确定性手势序列、期限边界、长按与双击互斥、旋转脉冲、取消、修饰键归属、配置校验、持久化失败、迁移及服务集成。测试使用替身发射器和临时存储，通过测试不等于实体系统快捷键已触发。[07](07-heartbeat-investigation.zh.md) 中之前的 Enter 与豆包 Fn 实测证明厂商到主机的路径，不代表每种新手势或应用动作都已实测。

演示界面已验证双击与长按分配和保存、设备图及控件列表同时显示动作、旋转控件仅允许即时动作。离线编辑与保存竞态由模型及服务测试覆盖；新增双击与长按快捷键的实体效果仍待设备实测。
