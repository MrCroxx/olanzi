> 📚 文档集：[README](../README.zh.md) · [02 协议](02-vibekey-protocol.zh.md) · [07 心跳](07-heartbeat-investigation.zh.md) · [09 原生 macOS](09-native-macos.zh.md) · **10 输入运行时**

## 1. 职责与范围

六个控件统一进入本机输入处理流程。菜单栏应用的设备工作线程持有接收器、心跳、手势时钟、已提交动作配置和合成按键状态。窗口只编辑草稿、提交配置，关闭窗口不会停止工作线程。它是进程内后台服务，不是另行安装的启动 daemon 或登录项；退出应用会停止转发。

上一版每次收到事件都查设备键位表，把硬件回退与运行时动作混在了一起，也没有识别双击和长按的位置。新运行时使用本机持久配置，仅首次从只读设备快照初始化。此后刷新与重连不会替换本机配置，日常编辑不再发送硬件键位表写命令。

| 层 | 职责 |
|---|---|
| `MacHIDTransport` | 解码厂商帧并投递物理控件边沿，查询等待期间同样投递 |
| `GestureRouter` | 根据边沿与单调时钟期限识别手势，选定互斥的配置动作 |
| `VendorKeyBridge` | 执行动作的按住状态、保留共享修饰键、重试失败的释放 |
| `MacKeyEmitter` | 把键盘 usage 转换为 macOS 事件，投递至 HID 层 |
| `HostKeymapStore` | 校验并原子持久化本机权威配置 |
| SwiftUI / `AppModel` | 编辑草稿、选择手势、导入导出配置、提交保存 |

厂商事件独立于配置动作标识控件。AU05 物理索引来自 `frame[4]`；`frame[2]` 是逻辑动作号，绝不作为键盘 usage 注入。四个可按压控件报告按下与松开边沿，旋转控件 4、5 每格仅报告按下脉冲。见[路径采集记录](evidence/2026-09-21-vendor-key-routing.log)。

## 2. 动作与时序

每个控件都有主要 `press` 动作。四个可按压控件还可以配置 `doublePress` 和 `longPress`。动作包含键盘条目，因此运行时可以保留已有键盘组合；当前选择器为所选动作分配一个键。可选动作缺失表示关闭该手势，分配“未分配”键则表示有意不执行。旋转控件拒绝双击与长按配置。

| 配置或事件 | 行为 |
|---|---|
| 没有可选手势 | 主要动作立即按下，随实体松开释放，Fn 和修饰键不增加手势延迟。 |
| 仅配置长按 | 阈值前松开发送一次主要动作脉冲；达到阈值后开始长按动作，保持至松开。 |
| 配置双击 | 第一次松开后等待双击窗口，到期发送一次主要动作脉冲。 |
| 双击期限前第二次按下 | 进入第二击候选，第二次松开后发送一次双击动作脉冲。 |
| 第二次按压达到长按阈值 | 已配置的长按优先，不再补发等待中的主要或双击动作。 |
| 第二次按下恰好到期或已过期 | 先结算第一次主要动作，再由新的按下开始一轮手势。 |
| 旋转一格 | 立即发送一次主要动作的按下与松开，不等待设备释放。 |

默认双击窗口从第一次松开起计 250 ms，长按阈值从对应按下起计 500 ms。配置允许双击窗口 150–500 ms、长按阈值 300–2000 ms，长按阈值必须大于双击窗口。计时使用单调时钟，重复按下报文不会重置按住状态或期限。

启用可选手势必然会推迟尚不能判定的主要动作。如果某个控件需要立即作为 Fn、Shift 等按住修饰键使用，应关闭其可选手势。把长按动作分配为 Fn，则会在达到阈值后才开始按住 Fn。

## 3. 配置与迁移

活动映射保存于 `~/Library/Application Support/Olanzi/host-keymap.json`，包含六个唯一控件索引、动作条目、时间参数和格式版本。存储先校验再原子替换，持久化失败时不激活新配置。文件缺失才允许从首次设备快照初始化；损坏或不支持的文件会报错，不会静默重置用户配置。

设备键位表是独立回退：应用退出、接收器恢复标准 HID 直出后使用。编辑回退仍是[03 · 工具手册](03-tool-manual.zh.md)中的显式协议工具操作，应用本机映射或导入配置不会改写它。本机配置初始化后支持离线编辑和保存；演示模式仅用内存，绝不接触真实本机存储或设备。

导出的 `HostProfile` 版本 2 包含完整映射和时间参数。导入兼容旧版原生应用的版本 1 六键码配置，将其转为主要动作并关闭可选手势。已保存配置集合使用 `nativeHostProfiles`，旧 `nativeProfiles` 集合作为迁移来源保留。导入限制为 32 KiB，并拒绝非法版本、重复或缺失控件、不支持的键、非法时间参数及旋转手势映射。

## 4. 按住、取消与失败处理

已发送的按住动作持有自身配置快照。同一个 Mac 键在不同控件间按引用计数管理，包括 Print Screen 与 F13 这类别名；释放一个控件不会提前释放另一个控件的键。事件标志保留其他仍在按住的修饰键，每格旋转都由主机补齐释放。

断连、在线状态或权限丢失、系统睡眠、配置替换及退出都会取消未判定手势，并尝试释放本服务持有的按键。取消不会把延迟单击补发到新聚焦的应用。配置切换时仍按住的实体控件会等待物理松开后再接受新手势，防止把已有按住状态误解释成新配置动作。释放失败会保留待重试状态，不会当作已成功。睡眠通知立即阻止输入回调，工作线程随后取消手势并关闭连接；唤醒后仅在用户此前没有手动断开时重连，不补发睡前待判定动作。

设备查询等待期间继续投递物理事件，因此回读不会把整个 Fn 按住过程压缩成查询结束后的两条事件。手势期限由后台工作线程维护，输入行为不依赖窗口计时器。未知动作类型和不支持的 macOS usage 明确报错，不猜测注入；此实现没有 F21–F24 的可用虚拟键映射。

## 5. 验证与扩展边界

120 项原生测试（108 项核心、12 项应用模型）已通过。自动测试覆盖确定性手势序列、期限边界、长按与双击互斥、旋转脉冲、取消、修饰键归属、配置校验、持久化失败、迁移及服务集成。测试使用替身发射器和临时存储，通过测试不等于实体系统快捷键已触发。[07](07-heartbeat-investigation.zh.md) 中之前的 Enter 与豆包 Fn 实测证明厂商到主机的路径，不代表每种新手势或应用动作都已实测。

演示界面已验证双击与长按分配和保存、设备图及控件列表同时显示动作、旋转控件仅允许即时动作。离线编辑与保存竞态由模型及服务测试覆盖；新增双击与长按快捷键的实体效果仍待设备实测。

本地运行检查与构建：

```bash
make test
make check-docs
make release
```

PR 工作流还检查旧协议测试，并使用 CI 临时签名构建 DMG。CI 产物不是公证发行版，也不使用开发者本机签名私钥。未来可以在手势选定动作之后新增动作类型，无需修改 USB 协议，也无需把输入行为耦合到 SwiftUI。宏、启动应用和多媒体命令不会因为这项设计自动启用。
